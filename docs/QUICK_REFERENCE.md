# Quick Reference: Multi-User Dynamic Kit Overview

## 🎯 Three-Line Summary

The kit will be **fully automatic** for any user. They run `setup.sh` → system auto-detects their project structure and tools → generates all configs → hooks work immediately. No manual editing needed.


### **New Way** ✅
```
Hook runs
    ↓
Source config_loader.sh
    ↓
1. Check env var ($BACKEND_DIR)
2. Check .claude/config.local.json (user)
3. Check .claude/config.json (team)
4. Auto-detect from filesystem
5. Fall back to default
    ↓
✓ Found! Path is correct for this user's setup
    ↓
Continue hook logic
```

## 💡 Key Concepts

### **1. Config Layering (Smart Defaults)**
```
User can customize ANYTHING at MULTIPLE levels:

Environment Variable (highest priority)
    export BACKEND_DIR=/custom/path
                ↓
User Config (.claude/config.local.json)
    {"paths": {"backend_dir": "/custom"}}
                ↓
Team Config (.claude/config.json)
    {"detection": {"backend_folders": ["backend", "api"]}}
                ↓
Auto-Detection
    Scans filesystem for common patterns
                ↓
Hardcoded Default
    backend/, frontend/

Result: Team defines good defaults, user can override if needed
```

### **2. Hook Intelligence (Skip if Irrelevant)**

```
Hook execution flowchart:

  Check enabled?
    ├─ No → Skip (not configured for this project)
    ├─ Yes ↓
  
  Tool available?
    ├─ No → Warn + Skip (user will see install suggestion)
    ├─ Yes ↓
  
  Right folder?
    ├─ No → Skip (file not in relevant directory)
    ├─ Yes ↓
  
  Run hook! ✓

Result: Hooks never fail, gracefully adapt to what's available
```

### **3. Role-Based Guidance (Right info for right person)**

```
After setup, system knows user role:

Backend Developer
  ├─ See hooks: Alembic, auto-format Python, migrations
  ├─ Get guide: Backend Developer Quick Start
  ├─ Warnings: Schema drift, migration reminders
  └─ Common tasks: Edit models, create migrations

Frontend Developer  
  ├─ See hooks: ESLint, TypeScript check, prettier
  ├─ Get guide: Frontend Developer Quick Start
  ├─ Warnings: Type errors, lint failures
  └─ Common tasks: Edit components, type safety

Full-Stack Developer
  ├─ See hooks: ALL (auto-adapts to what you edit)
  ├─ Get guide: Full-Stack Quick Start
  ├─ Warnings: Everything (you handle everything!)
  └─ Common tasks: Varies by file type
```

## 🎨 What Each Config File Does

### **`config.json` (Team Defaults - Checked In)**
```json
{
  "project_type": "fullstack",
  "detection": {
    "backend_folders": ["backend", "api", "server"],
    "frontend_folders": ["frontend", "web", "apps/web"]
  },
  "tools": {
    "python": ["black", "ruff", "isort"],
    "typescript": ["eslint", "prettier"]
  },
  "hooks": {
    "enabled_hooks": [
      "01_alembic_preflight",
      "03_branch_protection",
      "04_precommit_quality",
      "05_py_autoformat",
      "06_ts_eslint_fix"
    ]
  }
}

Purpose: Team says "here's what we use"
Used by: Every team member (shared baseline)
```

### **`config.local.json` (User Overrides - Not Checked In)**
```json
{
  "user": {
    "name": "Alice",
    "role": "backend"
  },
  "tool_overrides": {
    "python.formatter": "ruff",
    "skip_hooks": ["07_ts_typecheck"]
  }
}

Purpose: User customizes without breaking team setup
Used by: Only this user on this machine
```

### **`settings.local.json` (Generated - Hook Wiring)**
```json
{
  "hooks": {
    "PreToolUse": [...],
    "PostToolUse": [...]
  }
}

Purpose: Wires up which hooks run when
Generated by: setup.sh (users don't edit)
```
